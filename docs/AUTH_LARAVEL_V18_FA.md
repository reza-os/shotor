# مرحله ۱۸: لوگو و ورود / قرارداد آینده Laravel

## چه چیزی الان اجرا می‌شود؟

- لوگوی شرکت در Launcher اندروید و بالای صفحه ورود استفاده می‌شود.
- صفحه ورود قبل از بارگذاری داشبورد و قبل از شروع دریافت Wi-Fi باز می‌شود.
- نام کاربری و رمز عبور فقط به Laravel API ارسال می‌شوند؛ داخل APK حساب کاربری یا رمز ثابت وجود ندارد.
- تا قبل از راه‌اندازی سایت، دکمه «ورود آزمایشی بدون API» در حالت **debug/profile** فعال است؛ در **release** فقط در بیلد آزمایشی با فلگ صریح فعال می‌شود و در بیلد نهایی غیرفعال است.
- با خروج، اتصال آنتن متوقف، ارسال‌های زمان‌بندی‌شده SMS مکث و توکن محلی پاک می‌شود.
- توکن Laravel با flutter_secure_storage روی گوشی به‌صورت رمزنگاری‌شده نگهداری می‌شود؛ رمز عبور ذخیره نمی‌شود.
- در راه‌اندازی بعد، فقط با اعتبارسنجی `GET /auth/me` داشبورد باز می‌شود.

## قراردادی که باید روی Laravel پیاده شود (هنوز سروری متصل نیست)

آدرس API از بیرون کد تنظیم می‌شود:

```powershell
flutter run --dart-define=API_BASE_URL=https://api.example.com
```

در صورت نیاز، مسیرها قابل تغییرند:

```powershell
flutter run --dart-define=API_BASE_URL=https://api.example.com --dart-define=AUTH_LOGIN_PATH=/api/v1/auth/login --dart-define=AUTH_ME_PATH=/api/v1/auth/me --dart-define=AUTH_LOGOUT_PATH=/api/v1/auth/logout
```

### ۱. ورود

`POST /api/v1/auth/login`

```json
{"username":"herder1","password":"<user entered password>","device_name":"Shotor Android"}
```

پاسخ موفق `200`:

```json
{"token":"<Sanctum personal access token>","user":{"id":12,"name":"ساربان","role":"herder"}}
```

پاسخ ناموفق `401` یا `422` بدون توکن.

### ۲. بازیابی نشست

`GET /api/v1/auth/me` با هدر `Authorization: Bearer <token>`:

```json
{"id":12,"name":"ساربان","role":"herder"}
```

### ۳. خروج

`POST /api/v1/auth/logout` با Bearer token باید توکن جاری را در Laravel لغو کند.

**نکته:** SPA ری‌اکت می‌تواند از احراز هویت Session/CSRF خود استفاده کند، ولی برنامه موبایل از توکن Sanctum استفاده می‌کند. سرور باید مجوز دسترسی به گله‌ها را بر اساس کاربر بررسی کند؛ نباید فقط به داشتن توکن اکتفا کند.

## مراحل بعدی همگام‌سازی (عمداً هنوز پیاده نشده)

- POST/PUT عکس و مشخصات شتر روی Laravel از طریق API احراز شده و مالکیت گله.
- GET لیست شترهای مجاز کاربر و بازیابی در صورت نصب مجدد.
- نگهداری نسخه/تاریخ به‌روزرسانی رکورد برای حل تعارض و Sync صف آفلاین.
- جداسازی داده محلی بر اساس شناسه کاربر و گله؛ فعلاً دیتابیس محلی تاریخی حفظ شده و **بین حساب‌های مختلف روی یک گوشی جدا نشده است**. پیش از راه‌اندازی چندکاربره باید اجرا شود.

## نکات امنیتی و نصب

- در نسخه Release فقط HTTPS برای API پذیرفته می‌شود.
- ساخت APK آزمایشی (فقط برای تست و توزیع محدود): `flutter build apk --dart-define=ENABLE_TEMPORARY_DEMO_LOGIN=true`؛ برای انتشار واقعی این فلگ را **حذف** کنید.
- اکنون سرویس Laravel وجود ندارد و «ورود واقعی» بدون `API_BASE_URL` کار نمی‌کند؛ استفاده از ورود آزمایشی برای توسعه است، نه یک احراز هویت واقعی.
- FlutterSecureStorage روی Android SDK 23 به بالا پشتیبانی می‌شود. برای جلوگیری از بازیابی ناسازگار کلید Keystore، Android auto-backup برنامه غیرفعال شده است؛ بک‌آپ اختیاری شترها در خود برنامه باقی است.
- اگر گوشی در شبکه آنتن بدون اینترنت باشد، **ورود اولیه واقعی** و **اعتبارسنجی نشست در آغاز مجدد اپ** نیازمند راهکار آفلاین معتبر در مرحله بعد است؛ فعلاً برای حفظ امنیت، بدون تایید سرور وارد حالت واقعی نمی‌شود.
- خروج از حساب فایل‌های شتر را از دستگاه پاک نمی‌کند.
